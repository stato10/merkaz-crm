# פיילוט CRM למוקד שירות

## הפעלה מקומית

נדרש Python 3.10 ומעלה. מתיקיית הפרויקט:

```powershell
python server.py
```

פתחו [את סביבת הפיילוט](http://127.0.0.1:8877). אם הפורט תפוס, הריצו `python server.py --port 0` ופתחו את הכתובת שהשרת מציג. מסד SQLite נוצר מקומית בפעם הראשונה. ניתן להגדיר נתיב אחר במשתנה הסביבה `CRM_DB`.

1. בחרו את תור ההדגמה ושאלו ״מתי התור שלי?״.
2. כתבו ״אני רוצה להזיז את התור״, בחרו מועד חדש ואשרו.
3. כתבו ״אני רוצה נציג״. הפנייה תופיע בתור עם ההקשר והמועד המעודכן.
4. רעננו את הדף כדי לראות שהתור והפנייה נשמרו. במסך נציג נוסף הנתונים מתעדכנים אחת לחמש שניות.
5. דפדפן תומך יכול להזין את הבקשה מהמיקרופון בעברית. לאחר זיהוי הדיבור בודקים את הטקסט ולוחצים שליחה. הקראת תשובות תלויה בקולות הזמינים במכשיר.

## התאמה לארגון

```powershell
python server.py --create-org acme "מוקד שירות לדוגמה"
```

הפקודה מחזירה מפתח גישה. במסך ״החלפת ארגון״ הזינו את המזהה והמפתח. בהגדרות הארגון אפשר לשנות את שם המוקד וברכת הפתיחה. לכל ארגון תורים, פניות ופעולות משלו. ארגון חדש מתחיל ריק.

## API לחיבור מערכת חיצונית

חוזה הממשק זמין בקובץ `openapi.json`. בארגון אמיתי המפתח הראשון שייך למנהל עם המזהה `owner`. להנפקת מפתח אישי לנציג ומפתח נפרד למחבר:

```powershell
python server.py --issue-key acme agent-1 agent
python server.py --issue-key acme scheduler integration
```

הנפקה חוזרת לאותו מזהה מחליפה את המפתח הקודם. מפתח נציג מאפשר גישה לעמדת הנציג וטיפול בפניות. מפתח אינטגרציה מאפשר הזנת תורים וביצוע פעולות דרך ה־API. מנהל יכול גם לשנות הגדרות ולקרוא את `GET /api/v1/audit`, שמחזיר עד 100 פעולות אחרונות עם זהות המבצע. בעת שדרוג, יש לעצור את השרת הקודם לפני הפעלת הגרסה החדשה. המפתחות הארגוניים הקיימים ימשיכו לעבוד כמפתח של המנהל `owner`.

יש לשלוח `X-Organization` ו־`Authorization: Bearer <token>`. בקשות כתיבה מקבלות JSON. החזיקו את המפתח בצד השרת של האינטגרציה.

| ממשק | קלט |
| --- | --- |
| `POST /api/v1/appointments` | `id`, `customer`, `slot` בפורמט `YYYY-MM-DDTHH:mm` |
| `POST /api/v1/operations` | `requestId`, `appointmentId`, `action` מסוג `status`, `reschedule` או `handoff` |
| שינוי תור | שלחו גם `slot` ו־`previousSlot`. הממשק מחזיר 409 אם המועד הקודם השתנה או אם המועד החדש תפוס. |
| העברה לנציג | שלחו גם `summary`. הממשק מחזיר את מזהה הפנייה. |
| `GET /api/v1/dashboard` | פרופיל ארגון, תורים, פניות ופעולות אחרונות |
| `POST /api/v1/cases/close` | מזהה פנייה בשדה `id` |
| `POST /api/v1/settings` | `name` ו־`welcome` |

לאחר ניתוק, אפשר לשלוח שוב את אותה פעולה עם אותם שדות ואותו `requestId`. אם הפעולה כבר נשמרה, התוצאה המקורית תוחזר. בקשה שונה עם אותו מזהה מחזירה 409. זמינות התורים מדומה כמשאב אחד לארגון. השעות נשמרות כשעה מקומית כפי שנשלחה.

## חיבור לקוח ראשון

הגרסה מיועדת להרצה מקומית עם נתוני דוגמה. המענה מבוסס על זיהוי ביטויים, עם יכולות הדיבור של הדפדפן. לפי הדפדפן, זיהוי הדיבור עשוי לעבד שמע בשירות חיצוני. ההעברה יוצרת פנייה בתור, וה־API מאפשר למערכת חיצונית להזין תורים ולהפעיל פעולות.

לפיילוט עם ארגון בפועל יש לחבר סביבת בדיקות של מערכת הליבה, לקבוע מי מנהל את זמינות התורים, ולבדוק שינוי מועד עם אישור ממנה. לפריסה עם מידע אמיתי נדרשת תשתית שרת לייצור עם HTTPS, זהויות והרשאות למשתמשים, מפתחות חיבור מנוהלים, ניטור וגיבוי. מרכזייה או מנוע קול בזמן אמת יכולים להתחבר דרך פעולות ה־API לאחר התאמת המחבר.
